# L06_SMALL_REAL_SCENARIO_AUDIT_PARITY Stage Design

## Objective

L06 makes the committed six-node real Valkey scenario set a control group for later scale work. The stage must prove parity across audit, metric, and report layers for:

1. cluster smoke
2. management ops
3. workload smoke
4. observability smoke
5. fault sandbox
6. failover primary stop
7. stability soak
8. cleanup

The stage output is a machine-readable parity audit artifact. Report files remain views over JSON/JSONL source artifacts.

## Source-Of-Truth Inputs

The L06 audit reads source artifacts under `artifacts/phases/P03_LOCAL_DOCKER_VALKEY` through `artifacts/phases/P11_STABILITY_SOAK`, especially:

- `valkey_e2e_evidence.json` from wrapper-produced real gates.
- Scenario reports such as `management_ops_report.json`, `workload_report.json`, `fault_report.json`, `failover_report.json`, and `stability_report.json`.
- `metrics_timeseries.jsonl` and `events.jsonl` for observability.
- `cleanup_report.json` for every small-real surface.
- Existing JSON source artifacts in `artifacts/loop_engineering/reports`, never rendered HTML/SVG/CSV/Markdown as measured metric sources.

## Harness Design

Add a new schema and script:

- `schemas/artifact/small_real_parity_audit.schema.json`
- `scripts/audit_small_real_scenario_parity.py`

The script emits:

- `artifacts/loop_engineering/reports/small_real_parity_audit.json`

The audit must include one entry per required L06 surface, source artifact hashes, schema checks, fake and real coverage records, normalized metric extraction, cleanup linkage, report checks, and findings.

## Real Evidence Semantics

Normal six-node real evidence for P03/P04/P05/P06/P10/P11 requires:

- wrapper producer `scripts/valkey_e2e_gate.py`
- `status: PASS`
- `real_valkey: true`
- Valkey version prefix `9.1.`
- `nodes_observed: 6`
- `cluster_state_observed: ok`
- `data_path_result: PASS`
- cleanup status PASS

P07 fault sandbox requires:

- wrapper producer `scripts/fault_safety_gate.py`
- six nodes observed
- `data_path_result: SKIPPED_WITH_REASON` allowed only with explicit skipped semantics
- sandbox safety fields: `sandbox_only: true`, `host_network_mutated: false`, `global_firewall_mutated: false`, `fault_state_cleared: true`

P08 failover requires:

- wrapper producer `scripts/fault_failover_gate.py`
- starting state with six nodes
- post-primary-stop evidence with at least five live nodes
- promotion observed and failover latency measured
- `data_path_result: SKIPPED_WITH_REASON` allowed only with explicit skipped semantics
- `split_brain_duration_ms` remains `MISSING` with reason `not_measured_by_primary_stop_gate`

## Fake Parity

Fake fixture coverage is a deterministic test harness for the same surface/status model. It must not satisfy real coverage. Fake metrics use `evidence_layer: fake`, `evidence_class: fake`, and `real_valkey_coverage: false`.

## Report Parity

The report checks must prove measured, missing, skipped, and no-baseline statuses stay distinct. Measured values may not come from rendered `.html`, `.svg`, `.csv`, or `.md` views.

## P14 Boundary

L06 must not run `P14_SCALE_1000_OPTIN_DRYRUN`, set `VSLAB_ALLOW_1000_DRYRUN`, or count 1000-node dry-run/planner artifacts as real evidence. It may only preserve the existing dry-run boundary in report checks.

## Acceptance Criteria

- Previous harness remains PASS.
- L06 schema validates `small_real_parity_audit.json`.
- All eight surfaces have fake and real entries recorded separately.
- Real coverage is satisfied only by wrapper-produced real evidence and source artifacts.
- Cleanup passes with no residual resources for all required small-real surfaces.
- Split-brain duration remains explicit `MISSING` unless future real measurement exists.
- `SKIPPED_WITH_REASON` and `NO_BASELINE_YET` are preserved with nonempty reasons.
- Report checks distinguish measured, missing, skipped, and no-baseline values.
- CI includes the L06 parity gate without weakening prior gates.
- Review, validation, and anti-regression agents approve before commit.
