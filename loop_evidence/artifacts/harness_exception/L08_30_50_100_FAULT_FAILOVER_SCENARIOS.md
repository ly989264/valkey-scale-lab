# Harness Exception: L08_30_50_100_FAULT_FAILOVER_SCENARIOS

## Locked File

- `scripts/fault_failover_gate.py`
- `scripts/loop_engineering_validate.py`

## Defect

L08 requires real 30/50/100 Valkey fault/failover evidence from the pre-authored failover wrapper. The locked wrapper only supported the earlier P08 six-node shape:

- hard-coded `failover_setup` scenario;
- no named `--fault-report`, `--workload-window-report`, or `--cleanup-report` outputs;
- no before-fault node count in evidence;
- promotion detection could accept an unrelated surviving primary instead of the selected primary's replica;
- P13 scale scenarios used a 600-second `cluster-node-timeout`, preventing bounded failover observation in L08;
- setup intermediates were written into the shared phase artifact directory, which could overwrite scale-build artifacts;
- early workload windows were placeholders instead of live Valkey data-path samples;
- fault clear removed only local fault state for process-scoped node stops and did not prove restored cluster membership after clear;
- a single transient endpoint probe could fail the 100-node readiness check even when the cluster had full membership and converged on retry.
- the parser exposed `--require-data-path`, but the flag was not enforced, allowing future PASS evidence without required SET/GET proof.

The loop anti-regression validator also rejected deletion of tracked generated `.pyc` files under controlled paths, even though its own rule says generated bytecode must not be staged or tracked there. That defect prevented the stage from cleaning pre-existing bytecode pollution.

## Patch

The patch preserves and strengthens the wrapper requirement:

- accepts explicit scale fault/failover scenario names while mapping setup to existing `scale_30`, `scale_50`, and `scale_100` scenarios;
- emits the L08 named source artifacts for fault, failover, workload windows, cleanup, and real Valkey evidence;
- terminates only through the project fault API and records apply/clear latency;
- requires the expected replica of the stopped primary to become primary before promotion is counted;
- applies a scenario-local `CONFIG SET cluster-node-timeout` on owned Valkey endpoints before the fault so P13 scale failover can be observed within the gate window;
- isolates setup/intermediate artifacts under `_fault_failover_work_<scenario>` so shared P12/P13 build-metric artifacts are not overwritten;
- records live SET/GET workload windows against a slot owned by the selected failed primary before the fault, follows Docker-internal cluster redirects back through owned localhost endpoints, and rejects incorrect GET round trips;
- runs project cleanup inside the isolated `_fault_failover_work_<scenario>` directory and publishes only the L08 `cleanup_report_fault_<N>.json` artifact to the shared phase directory, preserving prior `cleanup_report_scale_<N>.json` artifacts;
- clears process-scoped node-stop faults by restarting the owned Valkey process from its recorded config and then independently probes after-clear membership;
- retries full-cluster readiness probes at scale without lowering the required 30/50/100 observed node counts.
- requires observed promotion to carry a numeric recovery timestamp rather than allowing PASS evidence with missing failover latency.
- enforces `--require-data-path` by failing the wrapper if before/after failed-primary-slot SET/GET proof is missing.
- allows pure deletion of controlled-path `.pyc`/`.pyo` files in anti-regression checks while continuing to reject added or modified generated bytecode.

## Before/After Behavior

- Before: P08 still worked, but L08 could not produce or audit required 30/50/100 source artifacts and could misidentify promotion.
- After: P08 command compatibility remains, and L08 produced passing real Valkey 30/50/100 fault/failover evidence with cleanup proof, after-clear membership proof, enforced data-path proof, and schema-valid measured workload-window artifacts scoped to the failed primary's slot range. The loop anti-regression check can now pass bytecode cleanup deletions without permitting new bytecode artifacts.
